# Source Deepening Pilot — 3対象横断報告 v001

調査日: 2026-09-25。基準: `research/reviews/300-entity-cross-review-v001.md`。対象は金長・六右衛門、花子さん、宗像市一覧6件のみ。**entities / sources / claims / schemas / validatorには変更を加えていない。** 詳細と個別URL・locatorは[金長・六右衛門](kinnaga-rokuemon/evidence-pack.md)、[花子さん](hanako-san/evidence-pack.md)、[宗像6件](munakata-six/evidence-pack.md)を参照。

## 今回確立した手順

1. 固定レビューのentity・claim・source IDと、その文言が実際に主張している範囲を転記する。
2. DB・一覧の**個別レコードID／行番号**を固定し、呼称の原表記、読み欄、話者、地域欄、掲載箇所、参照資料番号を分離する。類似検索は候補提示にとどめる。
3. DB・一覧が指す原掲載書誌を、刊行主体の目次、図書館・NDL等の所蔵目録で照合する。**書誌発見と本文到達を別のゲート**にする。同名別巻・再版・複刻を識別する。
4. 原掲載本文の該当頁を読めた場合だけ、その本文の表記・読み・筋を確認済みとし、DB要約との差分を記す。読めなかった場合は「未到達」とlocatorを残す。後世の機関解説・作品は別列に置く。
5. 資料刊行年、採話・記録時点、物語内時代、後世の再利用時点を混ぜない。地域欄は出典のラベルであって発祥地ではない。
6. 同名・同地・同類型から系譜や個体同一性を推定せず、entity grain・alias・claim修正は**候補**として記録する。Corpus反映は原掲載照合後の別工程とする。

## Source depthモデルの実用性・現schemaの不足

`Indexed` / `Source Deepened` / `Formation Trace Candidate` は、書誌発見を本文確認と混同しないために**実用的**だった。一方、今回すべて `Indexed` のままでも、(a) 個別レコード確認、(b) 原掲載書誌特定、(c) 本文照合、(d) 異時点の独立資料照合には大きな距離がある。Pilotレポート内ではその4ゲートを別記すれば足り、**現段階でschema変更を提案しない**。Formation Trace Candidateは「年代違い」だけでなく**資料の独立性**と追跡可能な属性（名・姿・役割）を確認してから強く認定する。Formation Tracedは今回認定しない。

将来Corpusへ深度を持ち込むなら、現schemaでは次が未表現・曖昧になりやすい: DBカードと原論文の**派生関係**、個別カードID・原掲載頁・原話の節を結ぶ多段locator、呼称・読みの**source別attestation**、刊行年と物語内年代の分離、資料アクセス状態、広い呼称単位と個別伝承／個体の関係。ただしこのPilotは報告上の不足指摘だけで、設計変更はしない。
