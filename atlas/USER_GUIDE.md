# 初めての利用：お菊を調べて根拠を持ち出す

この手順は代表10対象の入口を使わず、全件検索から始めます。対象例は「お菊（番町皿屋敷）」です。入力版は公開main `bf35b905…`（1000対象／744 source records／1052主張）。現存資料を今回新たに読み終えたという表示ではありません。

1. 起動した画面の検索欄へ `番町` と入力し、結果の「お菊（番町皿屋敷）」を選びます。必要なら名称・読み・地域・出典名・記述を空白区切りで追加します。
2. 比較欄で各出典の資料名、主張、資料内の位置を見比べます。「典拠を開く」で元ページへ戻れます。これは書誌・記述の併置であり、独立した異説の認定ではありません。
3. 図版の再利用条件を読みます。rights_noteは元記録であり、この道具が再配布許諾を認定した表示ではありません。外部図版はすべて持出し対象外です。
4. 「持出す根拠を選ぶ」で今回使うclaimだけにチェックを残します。初期状態は全件です。比較表示は全件のまま、持出すカードとZIPのみを絞ります。全件を外すと書出しできません。claim未収録の対象は、その不足を保った空カードを取り出せます。
5. 制作メモへ、例えば「この制作案では選択した資料の記述だけを参照する」と書きます。これは創作側のメモで、元claimに追加されません。
6. 「根拠付きZIPを取り出す」を押し、ダウンロード先からZIPを保存します。JSON／Markdownだけの書出しも選べます。
7. アプリを閉じてZIPを展開します。`README.txt`から始め、`card.json`のsourcesのsource_urlとclaimsのevidence_locationsを対応させて典拠を再発見します。`card.md`にも典拠リンクと位置があります。URLが失効していたら資料名・機関名・external_idと位置を手掛かりにします。リンクの将来の有効性は保証しません。
8. `export-manifest.json`でsnapshot_ref、収録／選択対象外claim ID、source ID、画像0件、ファイルごとのbytes／SHA256を確認できます。manifest自身は自己hash対象外です。`research-annotations.json`のkindはsummaryで、原文引用・翻刻ではありません。`comparison-relations.json`の未判定も引き継がれます。

`source_fact`は出典の記述についての事実、`reviewed`は既存の照合状態です。どちらも伝承の史実性や今回の再照合を保証しません。時期・地域も資料で確認した値で、発祥とは限りません。10対象のボタンは比較入口であり、10件の独立原典研究の完了報告ではありません。

制作メモはこのブラウザへ対象とsnapshot別に保存します。持出す根拠の選択は対象を開き直すと全件へ戻ります。選択結果は保存したカードとmanifestに残ります。共有・公開はこの画面から行いません。


## 未採用の修正候補7件

「修正候補を表示・exportへ含める」は初期状態で無効です。「候補を見る」の対象を選ぶと、その対象について元の文→候補文→元/候補locator→検証された層→未読範囲→未採用を見られます。元snapshotの主張は上書きしません。チェックを外すと元snapshotだけの表示・exportへ戻ります。

候補を含むZIP/JSONはoriginal_snapshotとcandidateを分離し、各候補のevidence_layerとadoption_state=not_adoptedを保持します。候補を根拠として新しい独立出典や確定史実へ数えません。claim_0761の文言とlocator変更は不可分で、瓶投げを死因とは断定しません。原資料のPDF・本文・画像は取り込みません。これは候補の持出しであり、元DBへの採用操作ではありません。
